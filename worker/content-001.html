01爬虫与反爬

需求场景

抓取微信公众号文章、评论区，用于做日报／行研。

实操路径

  • 搜狗当跳板：微信文章可借搜狗的公众号搜索接口抓取（搜狗抓不了评论区）。
  • 多渠道找同文：同一篇文章往往多渠道分发，微信抓不到就去门户网等其他渠道找。
  • 让 AI 先学 skill，别自己硬写：做爬虫前先让 AI 去 GitHub 找现成 skill，搜索关键词 spider ／ crawler + skill（如 spider skill），挑 star 多的用。
  • 不下载代码，只给网址：担心 GitHub 仓库藏「不干净的东西」，做法是把仓库网址复制给 AI，让它自己去学，不本地下载。
  • 反爬对抗：腾讯（微信）等对文章做了防 AI 抓取。高 star 的 skill 会用指纹浏览器、把身份标识伪装成真实用户来突破——skill 本质是工具，多数反爬能过。但确有防护做得极强的站点，即便有 AI 加持也爬不动。
  • 权限墙：部分资源需付费／登录，没有账号 AI 也拿不到。

傻瓜化操作两步法

  1. 把项目网页复制给 AI → 说「分析一下这个项目、我怎么用它、能否帮我爬取特定网站数据」→ 让它先模拟跑一遍确认能跑通；
  2. 确认 OK 后，直接让它安装 skill 并实际运行抓取。

延伸想法

做一个法律／投资专业的爬虫工具，把各大网站的会员权限池化，以付费方式把插件分享出去。

微信文章 → Obsidian 自动同步

  • 用 心知小助手（GitHub 上的插件，非 Obsidian 官方 community，需手动添加）：在微信里把文章转发给它，设置好路径后，只要电脑开着，每隔约 1 小时自动同步到本地 Obsidian，AI 即可读取。
  • 另一款 Cubox：免费版即可用，好处是还能同步到 Kindle。

02Skill 的封装与管理

  • Skill = 把自己独创的经验蒸馏成 markdown，本质是自然语言，跨工具通用（Claude Code、Kimi code、Open Code 都能读同一套 skill）。
  • 别指望直接复用网上的 skill：除非高度可复用，否则很难套到自己工作上——每个人对法律研究的格式、审美、严谨度要求都不同，无法通用。
  • 可链式组合 + 封装成斜杠命令：多个 skill 串起来（如「爬取 + 按指定格式生成」），封装成 /命令，未来新对话直接调用。
  • 痛点：skill 太多，AI 想不起来调用。解法：
    • 让 AI 把所有 skill 做一次整理，为每个 skill 生成命令，并画一张 skill 图谱；
    • 重复的合并、没用的删掉，保持唯一性；
    • 分层管理：项目级 skill 放各项目目录下（查找不易错）；系统级放 .claude ／ agent 文件；数量大时在根目录加图谱让 AI 自学调用。
  • 「PUA」式自我沉淀：要求 AI 每做完一件事、每次关窗口前都要复盘——「你做错了什么、我要求了你什么」，把经验固化成自己的流程／skill／pack；并让它维护一个 markdown 记录当前项目进度。

03格式与工具的效率账

分享人给出三条方法论 + 一份成本实测。

用对的格式和对的工具

MD ／ HTML 最适合 AI；Word ／ Office 不适合。非用 Office 不可时，要用对工具。

表 1　Word 处理方式成本实测（1800 字、61 段，按 Claude 5 定价）
操作成本
直接读 markdown≈ ¥0.1
用 office-cli 读 Word（约 1600 字）≈ ¥0.13
Python 解包读 Word≈ ¥0.45
Python 解包改格式≈ ¥3.31（md 的 33 倍）
  • Word 若走 pandoc／Python 解包，token 会从 4.6k 膨胀到约 100k，慢且易错。
  • 日报场景累积效应：每天读 md ¥0.1，一年 360 天 ≈ ¥25；换成解包方式则数百上千元。
  • office-cli（GitHub 开源脚本）：不解包，直接定位、直接改。原理是把 Office 渲染成图片，AI 能直接找到第几行／第几句去改，实操体感明显更快。与「漂亮模板类」的 skill 不冲突，可叠加使用。
  • 对照：Python 解包原理——docx 后缀改 zip → 解压出 styles ／ numbering ／ settings 等文件（Word 就是这些文件拼装出来的，分别决定编号、样式）→ AI 改 XML → 再打包回去，环节多、易出错。

用对的模型做对的事

  • 同一任务：最轻的模型约 7 秒，顶级大模型要几分钟。「对的模型」不一定便宜、也不一定大，按任务选。
  • 模型已明显分化（如 GPT-5.6 分三档），既省钱速度也有别。
  • 自动选模型：有公司自建「中转站」带 auto 模式自动选路由；千问、Kimi 也有「轻／重工作」之分（目前多为人工选）。

04保密纪要 ／ 本地化处理

场景

有录音，不想上云、不想用科大讯飞等公有服务。

流程

  1. 本地装语音模型（如 Whisper），让 AI 自己装即可——「语音转文字」这一步在本地完成，即完成脱敏；
  2. 转出文档后，再用可信的私有／公司大模型（也可用本地模型）把文字提炼成结构化纪要。

注意点

  • 本地模型可能不擅长区分发言人，且较耗资源；
  • 本地识别准确率低于公有云，但后续大模型提炼时能纠正部分识别错误，实测可用（甚至不比免费千问差）；
  • 本地部署门槛已很低（llama 等，什么电脑都能跑；Windows 带显卡更好，小模型也够写纪要）。分享者因公司有私有大模型，直接用了公司模型。

05音频 ／ 会议记录管理

需求

电话、客户会议等音频难以管理、归档、团队共享。

方案

  • 腾讯会议自带转写；来不及开会议软件时，用手机录音（非 iPhone 多可自动录音）→ 发给任意 AI 转文字。
  • 硬件：
    • Plaud（NotePin ／ Note）：贴在手机背面的卡片式录音器，录音 + 转写，云端，较贵（1000 多），专为商务人士纪要管理做过调优，效果最好；
    • Get 笔记外设、科大讯飞录音笔：转写已很成熟；
    • AirPods Pro 长时录音，放办公室 24 小时开着。
  • 愿景：把每天工作相关的电话、微信语音等信息汇集，自动生成总结 + 待办提醒。
  • 隐忧：Plaud 等上云后的保密性。

06语音输入工具

  • Typeless、闪电说、papi ／ Type（后二者为台湾产品）：语音输入法，能把你零散的口述结构化整理成文字。
  • 用法举例：回客户消息时说「先帮我写一段恭维、再帮我写……」，它会自动组织成有结构的文本。
  • 豆包输入法也有类似能力。要点：说话时尽量有结构，它整理效果更好；多为付费／试用后收费。

07Cowork 模式与模型切换

Claude 桌面端 Cowork 模式

  • 有独立对话窗口，且能读取本地文件夹（普通 chat 只能拖文件进去）。
  • 不推荐给易被封号的人：Cowork 约 2 倍 usage 消耗；一旦封号，只能通过链接下载 data（压缩包，邮件发得慢、24 小时有效）。
  • Claude 桌面端 Mac 版比 Windows 版稳定（Windows 常报错）。

跨厂商模型切换

  • CLI 里用斜杠命令换模型；
  • VS Code 装 Claude Code 插件 ／ Codex 插件，或用 GitHub Copilot，可在图形界面切换模型（GPT-5.6、Sonnet 4.6、Haiq 等），跨品牌跨厂商。需登录 subscription 或接 API（钱付给 Claude，不是付给 VS Code）。
  • 安装：在插件市场搜官方 Claude Code ／ Codex，只认官方插件。

08软件工程师视角（编程 + 多 Agent）

  • AI 编码演进：2023 ChatGPT → workflow（人工编排）→ 自主运行 → 现在的 skill + MCP 时代（用 skill 控制软件／工具）。
  • Superpowers：一个把软件工程专家知识封装进去的 skill 框架。用法：需求分析阶段对它说 brainstorming 头脑风暴 → 它逐步追问帮你完善需求（类似 plan mode）→ 再到设计、开发、测试。
  • 全流程模板化：需求分析 → 系统设计 → 开发 → 测试 → 代码审查，每阶段定制模板（类比法律文书模板），并用机制约束 AI 遵守编码规范、架构规范。
  • 提效数据：整体 20%–40%（各公司不同）。瓶颈不在编码，而在需求与测试阶段；传统流程的冗长人工审核最耗时。
  • 多 Agent 协作（探索中）：配备需求分析师、开发、测试等 agent，各自专注自己的 skill 领域，通过管线协同。
  • PPT：全部用 Claude 生成——把编码过程中的对话记录 + 成果，给个大纲让 Claude 自己提炼整理成可编辑 PPT（用其 doc ／ pptx skill）。缺点：极耗 token，一个 PPT 就能把订阅额度用完。

09虚拟机 ／ 云电脑方案

  • 大厂给每人本地装 Open Code（类 Claude Code）；因信息安全，改为虚拟机（云电脑，24 小时开机）操作。大厂可无限用 5（five）。
  • 三大好处：① 隔离；② 出门在外随处可访问；③ 满足境外模型需求。
  • 搭法：买一台云主机 → 部署 Open Code 服务端 → 接入模型 → 手机／国外均可访问。
  • 顺带解决「不懂电脑」痛点：在云端跑，发完指令就能走人。
  • 稳定／合规：用 AWS 等境外服务器不易被封；火山云、阿里云也有香港／全球节点，但国内服务商做这类事更易被监管。此法可省去单独翻墙。

10Claude Projects 用法

面向无编程基础者，纯从项目管理角度用 Claude 桌面端：

  • 一项目一 Project 文件夹：先写指示（角色、风格、语言等 basic 设置）+ 项目背景（客户是谁、要做什么），相当于给它灌输基础知识。
  • Context 区放项目基础文件（DD 报告、与客户的会议纪要等），后续改东西时 AI 自动读取。
  • Memories：对话多时会弹出 memories，把对话精炼成 memory；也可主动让它生成；每个项目有 summary。桌面端数据存本地电脑。
  • 保密隐忧：不脱敏的话，Project 信息会反哺训练大模型，存在 N 分之一概率在别人的建议里看到你的项目案例。
  • Artifacts：能生成预览（网页版左侧可预览）；好处是直接用 Claude 主力模型、无需配 API。

11MCP 打通数据源

  • Claude 桌面端还有 Cowork、Codex 账户配 computer use 等玩法。
  • Kimi 默认接入同花顺 MCP：几十块的 Kimi 订阅即可用同花顺，且免费、开放彻底（所有数据经 MCP 打通）。当前订阅难抢，需预约。
  • 行研／投资：可接数据库抓数据。
  • 法律的短板：案例数据基本不对外，裁判文书网都受限，更别提开放 MCP。

12Obsidian 插件与小技巧合集

  • 心知小助手：微信文章 → Obsidian 自动同步（见「爬虫与反爬」）。
  • Templater：定制化模板。
  • Open in VS Code：右键 md 用 VS Code 打开，编辑完回 Obsidian 看渲染效果；配合 VS Code 里的 AI 插件可直接对某段对话式修改。
  • 图片 asset 插件：粘贴图片时自动在同目录建 asset 文件夹并归档，md 与图片路径绑定——好处是 AI 读取时能同时读到文字和对应图片。
  • Quicker（与 AI 无关的小工具）：滚轮 + Ctrl 唤出截图 OCR、常用语、剪切板、快搜等；如「快搜」选中文字即可在 Google ／搜狗中搜索。
  • Quick Switcher（Obsidian 快捷键）：快速搜索定位。

13pandoc 排版工作流

  • pandoc：命令行格式转换工具，可配映射规则。
  • Obsidian + Share Command 插件：预设好 pandoc 语法后，一个快捷键就能把当前 md 转换成符合律所格式要求的 Word，直接在桌面生成文件。
  • reference 文档（reference.docx）：承载律所的格式要求（字体、行间距、编号、样式等）。作者把它开源到 GitHub——里面无内容、纯格式，可安全共享；用时用 AI 对话改字体大小等即可。
  • 封装成 skill：即一个 pandoc 转换器 + 映射规则。
  • 坑：pandoc 自带规则会让输出带「值得」水印，必须改 reference 覆盖。
  • 反向转换：docling——命令行工具，已嵌入右键菜单，右键把 Word ／ PDF 转成 md 用于知识管理，可批量。也是 GitHub 开源、让 AI 帮装即可。
  • 另有一法（作者不推荐）：利用 Word 的宏（Macro）功能让 AI 调用、实现对 Word 的编辑。
三种改 Word 方式对比（作者问 AI 的结论）：① pandoc 转 md 再改——快但会丢格式（每次转 md 就没格式，需重加）；② 解压 zip 改 XML 再封回——完整但环节多易错；③ office-cli 最快，一般首选。

14账号封禁与代理

  • 封号很快（秒封），可能诱因：IP、付款账号、邮箱、Cowork 高消耗等，防不胜防；有人三个账号全被封。
  • 代理推荐：Clash Party（作者认为比 Clash Verge 好用），节点自己找。
  • 关键设置：系统代理 + 虚拟网卡都要开，否则桌面端文件打不开；靠规则分流保证国内网站正常访问。
  • VPN ／账号来源等敏感信息约定「场外／私下」解决，不在群里发（会被封）。

15活动组织与共识

  • 缘起：组织者发现大家 AI 都用得很深但用法各异，线下深聊很有启发，遂发起这个纯技术、无商务的同好会（类似大学社团）。
  • 群组织：拟设一个大群（凡感兴趣者可入）+ 每期一个小群（限当期参会者），在大群里通知每期时间地点，报名参加。
  • 筛选原则：核心是「真的对这件事感兴趣」；过滤纯白嫖、功利／商务目的者；不追求人多，保唯一性。
  • 共识：律师圈把 AI 用得深的人不多，甚至有不少抵制者；AI + 保密需求是天然话题。聚焦「文字处理」这一共同点，纯技术分享可接受门槛，但要保持多样性，避免跨行太远（如纯诉讼话题）听不下去。
  • 控制「校友浓度」：不希望演变成校友会／律师局。
  • 展望：以后可去香港等地办；下期或邀一位做 TikTok 内部软件的朋友（字节）分享。志同道合、无功利，反而走得远。
